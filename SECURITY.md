# Security Policy

Gilbreth handles sensitive local activity data. Please report suspected
security or privacy vulnerabilities privately rather than opening a public
issue.

## Reporting a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/Tyler-Systems/Gilbreth/security/advisories/new).

Please include, when relevant:

- The affected Gilbreth version or commit.
- Your operating system and installation method.
- The impact and steps needed to reproduce the issue.
- Any suggested mitigation.

Do not include captured activity, credentials, personal information, database
contents, or unredacted logs unless they are essential to the report. If such
material is necessary, describe it first so a safer transfer method can be
agreed on.

This is a solo-maintained project, so no fixed response-time SLA is promised.
Reports will be reviewed as promptly as practical, and public disclosure should
be coordinated until a fix or mitigation is available.

For ordinary bugs and feature requests, use the issue tracker — see
[CONTRIBUTING.md](CONTRIBUTING.md).

## Supported versions

Security fixes target current `main` and the latest published build for each
platform. A platform's supported build may be attached to an earlier project
tag when a later tag did not include that platform. Older platform builds may
not receive patches.
